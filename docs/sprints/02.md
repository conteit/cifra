# Sprint 02 — Phase 1 completion

**Milestone:** Sprint 02 · **Closed:** 2026-09-11 · **Issues:** 13 closed, 0 carried
**Merged:** 48 commits, 18 PRs · **Tests:** 1283 unit, 122 story, 21 e2e
(from 791 / 62 / 8)

## What shipped

Phase 1 is complete: a user can sign in, create an encrypted vault, lock it,
and open it again — with a password or with the recovery phrase — on a real
Firebase identity, in Italian or English, installable as a PWA. Every Phase 1
requirement now has code behind it and a test that has been watched go red.

**Track A — prove the foundation.** The Firebase Auth emulator (#44) made local
sign-in and e2e sign-in possible with no secrets and no project; the build
guard in `vite.config.ts` proves the emulator branch cannot survive into
`build/client`. The encrypted db layer ran in a real browser for the first time
(#42) — and held: `Dexie.waitFor` is inert in Chromium but harmless (D20), and
the nine browser cases that proved it stay as the only place the middleware
executes under a real scheduler.

**Track B — the Sprint 01 review debt.** Date and type are bound into the record
AAD (#51, D18). Argon2id parameters read from the untrusted `meta` row are
bounded (#52, D19), then derivation moved off the main thread into a
one-per-derivation worker that hands back a non-extractable `CryptoKey` (#61,
D22), then the iteration count was re-measured and kept, with the target-device
assumption written down as a falsifiable cost model (#29, D23). The loading
button keeps focus (#54). Locale detection landed as four seams, not one (#47,
D21) — FOUN-07 is now true.

**Track C — the screens.** Sign-in, vault setup and unlock render from a
pathless *gate* that wraps the whole app rather than from a redirect (#9, D27);
the lock screen is that same gate, full-page, and the 30-minute idle auto-lock
plus the `pagehide` wipe close FOUN-10 (#10, D28). The recovery phrase — pulled
forward from the backlog because #9 must not ship vault creation without it —
wraps a second copy of the data key under an HKDF-derived key (#68, D26).

**Backlog pulled in on the way**, each because it was in the path of a track C
screen: the modal lets descendants own Escape (#56), the focus ring clears 3:1
on every surface (#65, D24), the install affordance (#60, D25), and the font
payload trimmed to latin + latin-ext (#63).

## The review gate

One pass over the whole merged diff (`6305906..main`, 119 files) before close.
**4 findings: 1 high, 2 medium, 1 low.** No path was found that yields
plaintext financial data or key material to a network peer or to storage; the
worker split, the KDF bounds, the recovery-phrase codec, the AAD read/write
symmetry, the emulator build guard and the Playwright wiring were read and
found clean.

The high finding was a real FOUN-10 hole, and it was in code written this
sprint:

- **A lock during an in-flight unlock was overridden by the outcome** (#90).
  Sign out while Argon2id runs, and the derivation finished into an unlocked
  vault with nobody signed in; the next Google account to sign in probed
  `isUnlocked === true` and walked into the previous user's vault with no
  password. The store now counts locks and discards any outcome that resolves
  after one.
- **An empty password reported an environment failure** (#91) — "reload the
  page" for a mistake the user can fix. The password path now has the twin of
  `phrase/malformed`.
- **`beforeinstallprompt` was captured minutes late** (#92) — a regression
  from #9 putting the gate in front of the layout that created the controller.
  FOUN-06, delivered by #60 in this same sprint, was false again by sprint end.
- **Vault creation is check-then-`put`** (#93) — two tabs can both create a
  vault and the loser holds a key that opens nothing. Deferred at `p2`.

All three `p1` findings were fixed inside the sprint (#94, #95, #96), each with
the failing test watched first.

### The theme: the seams between things that were each correct

Every finding sat at a boundary between two pieces that had been reviewed and
tested on their own. The store's `lock()` was right and the service's `unlock()`
was right; neither knew the other could happen mid-way. The KDF's input
validation was right and the store's environment mapping was right; the
rejection channel between them had a gap the recovery path had already closed.
The install controller was right and the gate was right; the gate moved the
controller's caller without anyone asking what the controller needed from time.

Sprint 01's lesson was that a guard must be shown to go red. This sprint's is
narrower and cheaper to act on: **when a change moves where something is
created or called, ask what that thing assumed about *when*.** Two of three
fixes were a one-line relocation once the question was asked.

## Carried out of the sprint

Nothing was silently dropped.

**Filed during the sprint:** #71 (the e2e relay flake, `p2`), #74 (language
override, `p2`, Phase 9), #78 (argon2id on a real phone, `p1`, `needs-human`),
#86 (retire the db seam once real UI writes an encrypted row, `p2`, Phase 3),
#89 (CSP and security headers, `p1`), #93 (the create race, `p2`).

**Two claims need the owner, not an agent:**

- **#78 is now a migration.** Its body said the argon2id measurement on a real
  phone had to happen *before the first vault existed*, because afterwards a
  change to the iteration count re-derives and re-wraps every master key. The
  first real vaults were created on 2026-09-11, on a phone and a laptop, before
  the measurement was taken. The measurement is still worth having; what it can
  cheaply change is not.
- **#89 was found while answering "can the idle lock be defeated from the
  console?"** Yes, trivially, and that is the accepted model — same-origin
  script already owns the data key. What is *not* acceptable is that an
  injected script has the same power, and today nothing but React's escaping
  stands in its way: no CSP, no `frame-ancestors`, no headers at all. Scheduled
  first in Sprint 03.

## Retro

**Worked.** Ordering the tracks by dependency, and writing the order into the
milestone description, meant the riskiest unknown (#42) was retired in the first
two days and every later PR built on a proven layer. Pulling #68 in front of #9
cost the due date and was the right call: a vault with no recovery path is a
product that destroys data on a forgotten password, and it would have shipped.
The `lock(reason)` signature caught a real bug (`onLock={lock}` would have stored
a `MouseEvent`) purely by making the argument required — types as guards, again.

**Didn't.** The sprint ran to its due date and closed on it only because the
review gate and its three fixes ran in a single afternoon. A `p1` requirement
(FOUN-06) was delivered and then silently un-delivered by a later PR in the same
sprint; nothing in `verify` knew that the install strip depended on *when* its
listener attached, and the e2e suite had no install case at all until #96. The
#78 window closed unnoticed: an issue that says "before X happens" needs X to
be a gate somewhere, and it was only a sentence.

Local testing collided with the e2e suite twice: a background emulator started
for a manual session blocked Playwright's own on :9099 (`reuseExistingServer:
false` did its job and said so). Same class as Sprint 01's stale preview; same
correct behaviour — refuse and name the port.
