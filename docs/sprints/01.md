## What shipped

Both Phase 1 tracks landed in full.

**Design track** — Editorial Italiana v2 as Tailwind 4 `@theme` tokens (#1): a raw
`--ramp-*` layer that generates no utilities, aliased by semantic tokens that are
the only surface components may touch (V1-3). Stock Tailwind namespaces are
cleared, so `bg-red-500`, `text-sm` and `md:` are build errors. Four primitives —
Button, Input, Card, Modal (#2) — and the responsive app shell (#3) satisfying
FOUN-09's 900px split with one nav item table and two arrangements.

**Core track** — the full key hierarchy: Argon2id KDF (#4), AES-KW wrapping and
AES-256-GCM record encryption (#5), the Dexie 4 DBCore encryption middleware with
its allowlist and plaintext-leak guard (#6). Integer-cent money parsing and
formatting (#7). Firebase identity and the session store (#8), decoupled from
encryption material by a mechanically-asserted import boundary.

**Fixed inside the sprint after review** — the WCAG contrast defect (#45) and the
two sprint-close fix PRs described below.

No user-facing product feature ships: no sign-in screen, no lock screen, no
transaction list. Those are #9 and #10.

## The review gate

A correctness + security pass ran over the whole merged diff before close, in two
halves. **23 findings: 2 high, 12 medium, 9 low. No critical.** No path was found
that yields plaintext financial data or key material, and `npm audit` was clean.

Two results were worth as much as the defects:

- **`money.ts` could not be broken.** Exhaustive enumeration of all strings ≤6
  chars over `{0,1,2,9,.,,,space}`: 16,320 parse, zero round-trip failures. Every
  well-formed en-US money string ≤7 chars: zero accepted with a different value.
  The silent 1000× path does not exist.
- **The crypto core held.** IV reuse is structurally impossible, AAD id-binding
  works, non-extractability is real.

### The theme: guards that looked like guards

Four independent findings, one pattern — mechanisms that appeared to enforce an
invariant while enforcing nothing. All four are now fixed and mutation-tested.

| Finding | Demonstrated failure |
|---|---|
| Import-graph boundary tests | 3 live module refs → **0 specifiers extracted** |
| V1-3 token scanner | file in `app/ui/sub/` with 5 violations → **122/122 pass** |
| Contrast guard | focus ring repainted to invisible cream → **all 84 pass** |
| e2e coverage | never tested the 900px boundary FOUN-09 specifies |

The boundary tests were the *sole* mechanical guard on "Firebase never touches
encryption material". They passed because nobody had yet written the import forms
they missed. Replaced with a TypeScript-AST walker whose own suite is 44 tests,
including one asserting the old regex missed what defeated it.

### The offline bug

**FOUN-05 was asserted as delivered and was false.** `sw.js` was written 78 ms
before `index.html` existed — React Router prerenders the shell *after*
vite-plugin-pwa globs `outDir` — so the shell was never precached and the
navigation route bound to a non-precached URL. The resulting throw was swallowed
in an unawaited promise, so the worker installed looking healthy and `verify`
stayed green.

Fixed by regenerating the worker after the shell is on disk, plus a build-time
guard that fails the build if the precache manifest lacks the navigation
fallback. The fix also caught what the review missed: **all 21 `.woff2` faces
were going to the network**, so the app would have rendered offline in fallback
system fonts even with the shell fixed. Precache: 16 entries/451 KiB → 39/927 KiB.

## Carried out of the sprint

Nothing was silently dropped. Every finding is an issue with a priority.

**Filed:** #51–#63 (13 issues). **Re-assessed in place:** #29 raised to `p1`;
#32, #33, #42 and #47 corrected with the review's verdicts.

Three verdicts changed what the team believed:

- **#42 is worse than it read.** Not "the `Dexie.waitFor` adapter is unproven in a
  browser" — *nothing in the app imports `app/db/` or `app/crypto/` at all*. The
  entire encrypted database layer has never executed in a browser. If `waitFor`
  is insufficient under a real scheduler, every write fails and `verify` stays
  green.
- **#32's threat model was wrong.** A parameter downgrade derives a *different*
  master key, so unwrap simply fails. The impact is denial of service and data
  destruction, not decryption. It stays `p2`; the bounds fix (#52) and the
  creation-time path were split out instead.
- **#47 is under-scoped** — four seams, not one. The app is English-only:
  nothing reads `navigator.language`, `home.tsx` imports `en` directly, and
  `<html lang="en">` is baked into the prerendered HTML. **FOUN-07 is not met.**

## Retro

**Worked.** Two parallel tracks on disjoint files produced no merge conflict
worth the name across nine issues. Requiring a mutation matrix per PR — break the
invariant, name the test that catches it, revert — caught vacuous passes
repeatedly, including two the authors found in their own suites. Writing every
judgement call into the PR body made the review gate cheap: findings were checked
against stated reasoning rather than reverse-engineered from a diff.

**Didn't.** Guards were written and trusted without anyone asking whether they
could fail. Four of them could not, and the pattern was only visible when someone
was told to attack them specifically. A green suite is evidence of nothing until
it has been shown to go red.

Two claims shipped as delivered while being false (FOUN-05 offline, FOUN-07
locales). Both were requirements nobody owned an issue for — the gap was in
tracking, not in engineering.

Test infrastructure misled agents four times via a stale `vite preview` on the
shared Playwright port. Fixed by refusing to reuse a server this run did not
start, rather than by documenting the trap.
